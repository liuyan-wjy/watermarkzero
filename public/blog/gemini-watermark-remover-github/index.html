Gemini watermark remover on GitHub

Published May 15, 2026 · Updated September 5, 2026

Use this page when you want to inspect the source, run the remover locally, or self-host the same visible Gemini watermark workflow behind WatermarkZero. The hosted site is at liuyan-wjy/watermarkzero; the upstream package and original engine live at GargantuaX/gemini-watermark-remover.

Repository roles

WatermarkZero is the website you open in a browser, with image tools, batch downloads, tutorials, and deployment files. GargantuaX/gemini-watermark-remover is the upstream MIT-licensed package that exposes the core remover, SDK, command-line tool, and userscript notes.

  • Use liuyan-wjy/watermarkzero when you want the deployed website source.
  • Use GargantuaX/gemini-watermark-remover when you want the reusable package, CLI, SDK, or userscript workflow.
  • Check the MIT license before copying package code into another app.
  • Test an original Gemini export before relying on the code for batch work.

Run this website locally

These steps use the WatermarkZero repository. They were checked with Node.js 22 and pnpm 10.11.0. Install both before starting. In your first terminal, clone the site and start the development server:

git clone https://github.com/liuyan-wjy/watermarkzero.git
cd watermarkzero
pnpm install --frozen-lockfile
pnpm dev

Open the local address printed by the server. Keep that terminal running while you use the tool. When finished, stop the development server with Ctrl+C before building, because both commands write to dist. From the same watermarkzero directory, build the site and process the included sample:

pnpm build
node bin/gwr.mjs remove src/assets/samples/debug1-source.png --output cleaned.png

The included debug1-source.png sample is 1376 × 768 pixels. The command writes a PNG at the same dimensions to cleaned.png; open it beside the source and inspect the lower-right corner. For your own files, replace the input path and choose a new output filename so you keep the original. Prefer original Gemini exports over screenshots or social-media copies, which can change the watermark pixels.

For the standalone SDK or userscript, follow the upstream README; its available commands may differ from this website fork.

Hosted tool vs self-hosted code

Option Best for Tradeoff
WatermarkZero web tool Quick browser cleanup with no local setup Limited to supported visible Gemini watermark patterns
Open-source GitHub project Auditing code, adapting UI, or self-hosting You own deployment, maintenance, and compatibility checks
UserJS workflow Advanced users who want browser automation Permissions and update safety need extra attention

Where to inspect the algorithm

Start with src/core/watermarkConfig.js for the known Gemini size and anchor rules, then read src/core/watermarkProcessor.js for detection, candidate selection, reverse-alpha restoration, and final safety metadata. The file-oriented path enters through bin/gwr.mjs and src/cli/gwrRemoveCommand.js.

The code should line up with the public explanation in How Gemini watermarks work: supported files are checked against expected visible Gemini mark patterns, restored locally where possible, and skipped when the match is too weak.

This code path is for the visible Gemini mark. If your goal is to turn off future marks in Gemini exports, read how to turn off Gemini watermark prompts and exports. If you are checking whether Gemini-generated writing can carry SynthID Text, read whether Gemini watermarks text.
